## 📍 Directory Structure — THE COMPLETE PICTURE

Hermes consists of **3 distinct directories** on **potentially different machines**. Understanding this is critical for deployment and troubleshooting.

### Local Installation (tp machine: 192.168.0.73)

```
/home/tp/projects/active/hermes/          ← SOURCE CODE (git repo)
├── .git/                                  ← Version control
├── hermes/                                ← Python package
│   ├── core/                              ← Orchestration logic
│   ├── tools/                             ← SSH, shell, diagnostic tools
│   ├── api/                               ← FastAPI HTTP server
│   └── notification/                      ← Alert system
├── tests/                                 ← Unit tests (353/353 passing)
├── vscode-hermes/                         ← VS Code extension
├── docs/                                  ← Documentation
├── .venv/                                 ← Python environment
├── ARCHITECTURE.md, CLAUDE.md, README.md  ← Key documentation
└── .hermes_setup.md                       ← THIS FILE
        ↓ (reads config & state from...)
        ↓
/home/tp/.hermes_data/                    ← RUNTIME DATA (NOT git-tracked)
├── config.json                            ← 🔑 YOUR CONFIG
│   ├── ollama_url                         ← LLM backend URL
│   ├── ops_model                          ← Primary AI model
│   ├── whitelisted_hosts                  ← SSH security whitelist
│   ├── ssh_key_path                       ← SSH authentication
│   ├── api_token                          ← HTTP bearer token
│   └── approved_models                    ← Model security allowlist
├── hermes.db                              ← SQLite task database (1.3MB)
├── audit/                                 ← Append-only JSONL audit logs
├── backups/                               ← Automated daily backups
├── chat_sessions/                         ← Bot session state
├── datasets/                              ← Training data
├── logs/                                  ← Runtime logs
└── models/                                ← Model metadata
```

### Remote Installation (garage-core: 192.168.0.249)

**Strategy:** Git clone with automated daily sync via cron

```
/home/garage_core/hermes/                 ← Git clone of main repo
├── .git/                                  ← Version control
├── scripts/
│   └── sync-from-main.sh                  ← Auto-sync script (runs daily at 2 AM)
├── hermes/                                ← Python package (synced from tp)
├── api_venv/                              ← Local Python environment
└── [synced daily from tp]                 ← CODE SYNC: automated cron job
        ↓
/home/garage_core/.hermes_data/           ← SEPARATE: garage-core specific data
├── config.json                            ← Points to localhost:11434 (local Ollama)
├── hermes.db                              ← garage-core's task history only
└── audit/                                 ← garage-core's audit trail only
```

**Deployment Strategy:**
- Code: synced daily at 2 AM via `scripts/sync-from-main.sh`
- Data: isolated per-machine (no shared database)
- Services: auto-restart on code update if configured
- Logging: all syncs logged to `/var/log/hermes-sync.log`

## 🔄 MIGRATION: `.hermes/` → `.hermes_data/`

### Why rename?
- **Clear:** `.hermes_data/` obviously means "data", not source code
- **Prevents confusion:** No one thinks it's the project itself
- **Better docs:** Easier to write "config is in `.hermes_data/`"

### Migration steps

**Step 1: Backup**
```bash
cp -r ~/.hermes ~/.hermes.backup-$(date +%s)
```

**Step 2: Rename**
```bash
mv ~/.hermes ~/.hermes_data
```

**Step 3: Test**
```bash
cd /home/tp/projects/active/hermes
source .venv/bin/activate
hermes ask "check disk on garage-core"
# Should work with config from ~/.hermes_data/config.json
```

**Step 4: Verify**
```bash
# Check config was read
ls -la ~/.hermes_data/config.json

# Check database still has history
sqlite3 ~/.hermes_data/hermes.db "SELECT COUNT(*) FROM tasks;"

# Check audit logs
ls ~/.hermes_data/audit/
```

**Step 5: (Optional) Create symlink for old scripts**
```bash
ln -s ~/.hermes_data ~/.hermes
```

## 🌍 DEPLOYMENT TO garage-core (FINAL STRATEGY)

### Architecture Decision: Automated Sync with Data Isolation

**Decision Summary:**
1. ✅ **Code:** Git clone with automated daily sync
2. ✅ **Sync mechanism:** Cron job at 2 AM (via `scripts/sync-from-main.sh`)
3. ✅ **Data:** Separate `~/.hermes_data/` per machine (isolated config, DB, logs)

### Setup Steps

#### Step 1: Clone Hermes code on garage-core

```bash
ssh garage-core
cd ~
git clone <your-repo-url> hermes
cd ~/hermes
```

#### Step 2: Create isolated data directory

```bash
mkdir -p ~/.hermes_data
```

#### Step 3: Configure for local Ollama

```bash
cat > ~/.hermes_data/config.json << 'EOF'
{
  "ollama_url": "http://localhost:11434",
  "ops_model": "gemma4:e4b",
  "reasoning_model": "gemma4:26b",
  "whitelisted_hosts": ["garage-core", "localhost", "127.0.0.1"],
  "ssh_key_path": "~/.ssh/id_ed25519",
  "api_token": "garage-core-secret-token",
  "approved_models": ["gemma4:e4b", "gemma4:26b", "garage-ai-v14:latest"]
}
EOF
```

#### Step 4: Set up automated daily sync

```bash
# On garage-core, add this to crontab:
crontab -e

# Add this line (syncs at 2 AM daily):
0 2 * * * /home/garage_core/hermes/scripts/sync-from-main.sh >> /var/log/hermes-sync.log 2>&1
```

**What the cron job does:**
- Fetches latest code from origin/master
- Checks if code actually changed
- Updates to latest version if changes exist
- Restarts Hermes services automatically
- Logs all actions to `/var/log/hermes-sync.log`

#### Step 5: Test the setup

```bash
# Verify sync script works
/home/garage_core/hermes/scripts/sync-from-main.sh

# Verify Hermes runs with local config
cd ~/hermes
source api_venv/bin/activate
hermes ask "check uptime"

# Verify database was created in isolated location
ls -la ~/.hermes_data/
```

### Data Isolation Explained

**Why separate data per machine?**

```
tp (192.168.0.73):
  ~/.hermes_data/config.json
    → ollama_url: "http://192.168.0.249:11434"  (points to garage-core)
  ~/.hermes_data/hermes.db
    → contains tp's task history only
  ~/.hermes_data/audit/
    → contains tp's audit logs only

garage-core (192.168.0.249):
  ~/.hermes_data/config.json
    → ollama_url: "http://localhost:11434"  (local Ollama)
  ~/.hermes_data/hermes.db
    → contains garage-core's task history only
  ~/.hermes_data/audit/
    → contains garage-core's audit logs only
```

**Benefits:**
- Each machine has independent configuration
- Task histories don't mix
- Backups are separate (easier recovery)
- Services can fail independently
- Scales to more machines (Pi 5 #2, etc.)

## 🐛 TROUBLESHOOTING

### "Config file not found"
```bash
# Create manually
mkdir -p ~/.hermes_data
cat > ~/.hermes_data/config.json << 'EOF'
{
  "ollama_url": "http://192.168.0.249:11434",
  "ops_model": "gemma4:e4b",
  "whitelisted_hosts": ["garage-core"],
  "ssh_key_path": "~/.ssh/id_ed25519",
  "api_token": "dev-token-insecure"
}
EOF
```

### "Database is locked"
```bash
pkill -TERM -f "hermes"
sleep 2
hermes ask "check disk"
```

### "SSH key permission denied"
```bash
chmod 600 ~/.ssh/id_ed25519
ssh -i ~/.ssh/id_ed25519 garage-core "uptime"
```
